\section{Capítulo: Requerimientos Funcionales y no Funcionales}

En este capítulo se especifican los requerimientos funcionales y no funcionales
según el modelo IEEE Std 830-1998, en los cuales 
se detallan las funcionalidades del sistema, así como los criterios de diseño
e implementación. Asimismo, se detallan los casos de uso segun 
correspanda al requerimiento funcional para garantiza el correcto diseño, implementación y validación del sistema 
propuesto.


\subsection{Módulo 1}

\begin{enumerate}
    % \ref{it:RF01} 
    \item \label{it:RF01} \textbf{RF01-Modos de operación} 
        \begin{enumerate}
            \item \textbf{Validez de las entradas}
                \begin{enumerate}
                    \item Se debe implementa un sensor de pH debe estar fabricado de un material de grado alimenticio que no contamine ni interfiera con el proceso de la fermentación, capaz operar en líquidos dentro de un rango de temperatura de 18 °C a 30 °C" y un rango de medición de pH de 4.0 a 7.0 con un tiempo de respuesta de máximo 1 minuto .
                    \item Se debe implementa un sensor de temperatura debe estar fabricado de un material de grado alimenticio capaz de trabajar en líquidos , sin contaminar ni interferir con la fermentación del kéfir, atraves de un rango de medición de 18°C a 30°C.
                    \item Se debe implementa un sensor de $CO_{2}$  debe ser capaz de medir en un rango de 0-10,000ppm en el aire dentro del frasco de fermentación, operando en el mismo rango de temperatura (18°C a 30°C).
                    \item Se debe implementa frascos con capacidad minima de 1 litro para asegurar que los sensores de pH y temperatura esten completamente sumergidos en la leche durante la fermentación .
                    \item Se debe implementa un formato de datos deberá integrar las lecturas de los sensores en un solo paquete, incluyendo un identificador único para cada conjunto de datos y una marca de tiempo.
                    \item Se debe implementa un una salida para la liberación del gas $CO_{2}$ en las tapas de los frascos, la cual estará conectada mediante una manguera a un segundo frasco con agua (no mayor a 1 litro), destinado a disolver el $CO_{2}$ generado durante el proceso.
                    \item Se debe implementa dos modos de operación(modo prueba y modo monitoreo), activados mediante dos botones físicos en el microcontrolador que, al presionarse, inicien el modo correspondiente y permitan salir del mismo al presionar nuevamente el botón.
                \end{enumerate}   
            
            \item \textbf{Secuencia exacta de operaciones}
                \begin{enumerate}
                    \item El sistema al entrar en modo prueba, deberá verificar el estado de los sensores al enviar los datos de los sensores cada 1 minuto exclusivamente a la página web para visualización temporal, sin almacenarlos en la base de datos.
                    \item En modo monitoreo, el sistema deberá verificar que el pH inicial de la leche esté entre 6.6 a 6.8 y su temperaturaesté entre 18°C a 30°C, en caso contrario, no iniciar el monitoreo y enviar una alerta a la base de datos.
                    \item En modo monitoreo, el sistema deberá verificar la conexión con la base de datos antes de iniciar la recolección de datos, y en caso de fallo, no iniciar el monitoreo y enviar una alerta.
                    \item En modo monitoreo, el sistema deberá iniciar la recolección y envío de datos a la base de datos.
                    \item En modo monitoreo, el sistema deberá enviar los datos recopilados por los sensores de pH y $CO_{2}$  cada 10 minutos si el pH está en el rango de 6.8 a 5.6.
                    \item En modo monitoreo, el sistema deberá enviar los datos recopilados por los sensores cada de pH y $CO_{2}$  cada 5 minutos si el pH está en el rango de 5.5 a 5.0.
                    \item En modo monitoreo, el sistema deberá recopilar y enviar los datos de los tres sensores (pH, $CO_{2}$  y temperatura) cada 1 minuto si el pH está en el rango de 5.0 a 3.9 en adelante.
                    \item En modo monitoreo, el sistema deberá recopilar y enviar los datos del sensor de temperatura cada 2.5 minutos de manera independiente, y ajustar la frecuencia a cada 1 minuto de todos los sensores si la temperatura supera los 28°C.
                \end{enumerate}   
        
            \item \textbf{Respuestas a situaciones anormales}
                \begin{enumerate}
                    \item El sistema genera una alerta y la registra en la base de datos si la comunicación con cualquier sensor (pH, temperatura, CO) se interrumpe ya sea en modo prueba o monitoreo.
                    \item El sistema retrasmite los datos recolectados por los 3 sensores en caso de un fallo en la conexión con la base de datos.
                    \item Si el pH supero el parametro de 3.9 , se genera una alerta y el sistema deja de sensar.
                \end{enumerate}   
       
            \item \textbf{Efecto de los parámetros}
                \begin{enumerate} 
                    \item El formato de datos soporta diferentes tipos de datos (números decimales para pH y temperatura, enteros para CO2, cadenas para ID y timestamp) en una estructura anidada, permitiendo flexibilidad para futuros sensores.
                \end{enumerate}   
        
            \item \textbf{Relación entre las salidas y las entradas}
                \begin{enumerate}
                    \item Los sensores proporcionan valores crudos y el formato de datos integra dichos valores de forma anidada.
                \end{enumerate}
        \end{enumerate}

    \item \label{it:RF02} \textbf{RF02-Cónexion del Microcontrolador a la Base de Datos}
        \begin{enumerate}
            \item \textbf{Validez de las entradas}
                \begin{enumerate}
                    \item Se debe implementa un protocolo de conexión que garantize la conexión de multiples microcontroladores de manera simultanea e independiente.
                    \item Se debe implementa un protocolo de conexión que permita la identificación única de cada microcontrolador mediante un ID.
                \end{enumerate}   
            
            \item \textbf{Secuencia exacta de operaciones}
                \begin{enumerate}
                    \item El microcontrolador establece la conexión con la base de datos al encenderse y verificar la conexión antes de enviar cualquier dato.
                \end{enumerate}   
        
            \item \textbf{Respuestas a situaciones anormales}
                \begin{enumerate}
                    \item El sistema registra en un log todos los intentos de conexión fallidos al servidor de base de datos.
                \end{enumerate}   
       
            \item \textbf{Efecto de los parámetros}
                \begin{enumerate} 
                    \item El protocolo de conexión mantiene escalabilidad para soportar un aumento en el número de microcontroladores conectados sin degradar el rendimiento.
                \end{enumerate}   
        
            \item \textbf{Relación entre las salidas y las entradas}
                \begin{enumerate}
                    \item El protocolo de conexión del microcontrolador asegura compatibilidad con el servidor de base de datos para asegurar la correcta transmisión de datos.
                    \item El protocolo de conexión incluye que los datos enviados a la base de datos incluyan una marca de tiempo para cada lectura, permitiendo un seguimiento preciso de la evolución de los parámetros monitoreados.
                    \item El protocolo de conexión garantiza que los datos enviados a la base de datos estén en el formato requerido por el módulo de análisis de datos para su procesamiento posterior.
                \end{enumerate}
        \end{enumerate}

    \item \label{it:RF03} \textbf{RF03-Microcontrolador}
        \begin{enumerate}
            \item \textbf{Validez de las entradas}
                \begin{enumerate}
                    \item Se debe implementa un microcontrolador que disponga las entradas analógicas necesarias para conectar los sensores de pH, temperatura y $CO_{2}$.
                    \item Se debe implementa un microcontrolador que cuente con memoria suficiente para almacenar datos temporalmente en caso de fallos de conexión con la base de datos.
                    \item Se debe implementa un microcontroladror que incluya la conexión requerida para hacer uso del protocolo de conexión.
                    \item Se debe implementa un microcontrolador que gestione la lógica de control para los dos modos de operación (prueba y monitoreo) y ajustar la frecuencia de recolección de datos según los parámetros medidos.
                \end{enumerate}   
            
            \item \textbf{Secuencia exacta de operaciones}
                \begin{enumerate}
                    \item El microcontrolador adquiere los datos de los sensores de manera secuencial (primero pH, luego $CO_{2}$ , luego temperatura) en cada ciclo de medición para optimizar el procesamiento.
                \end{enumerate}   
        
            \item \textbf{Respuestas a situaciones anormales}
                \begin{enumerate}
                    \item El sistema emite una alerta y se registra en la base de datos ,si la comunicación con cualquier sensor (pH, temperatura, CO) se interrumpe ya sea en modo prueba o monitoreo.
                    \item El sistema retransmite los datos recolectados por los 3 sensores en caso de un fallo en la conexión con la base de datos.
                    \item El sistema documenta en un log todos los intentos de conexión fallidos al servidor de base de datos.
                \end{enumerate}   
       
            \item \textbf{Efecto de los parámetros}
                \begin{enumerate} 
                    \item El microcontrolador modifica la frecuencia de recolección de datos en función del rango de pH medido y la temperaura, como se especifica en la secuencia de operaciones.
                    \item La alimentación del microcontrolador mantiene estabilidad y adecuación para garantizar el funcionamiento continuo durante el proceso de fermentación, considerando al menos un intervalo de 12 a 48 horas de operación ininterrumpida.
                \end{enumerate}   
        
            \item \textbf{Relación entre las salidas y las entradas}
                \begin{enumerate}
                    \item El microcontrolador procesa lecturas crudas(haciendo la conversión de datos analogicos a digitales) de los sensores y genera paquetes de datos estructurados junto con un identificador del microcontrolador para su envío a la base de datos.
                \end{enumerate}
        \end{enumerate}
    \item \label{it:RNF01} \textbf{RNF01}
            \item \begin{enumerate}
                    \item El sistema debe ser capaz de manejar múltiples conexiones simultáneas de microcontroladores sin degradar el rendimiento.
                    \item El sistema debe ser escalable para soportar un aumento en el número de microcontroladores en base al crecimiento de usuarios.
                    \item El sistema debe perimitir analizar diferentes cepas de bulgaros y diferentes tipos de leches.
            \end{enumerate}
\end{enumerate}

\subsection{Módulo 2}\
\begin{enumerate}
\item \label{it:RF04} \textbf{RF04-Análisis de datos}
        \begin{enumerate}
            \item \textbf{Validez de las entradas}
                \begin{enumerate}
                    \item Se valida que los datos recibidos de la base de datos estén completos y no contengan valores nulos.
                    \item El módulo 2 recibe los datos en el formato especificado por el módulo 1 con su respectivo ID.
                    \item El módoulo 2 realiza el análisis de los datos de acuerdo a los datos de cada usuario.   
                \end{enumerate}   
            
            \item \textbf{Secuencia exacta de operaciones}
                \begin{enumerate}
                    \item El sistema inicia el analisis automáticamente los datos conforme estos sean recibidos, ejecutando el proceso de análisis en tiempo real a medida que llega nueva información desde los sensores.
                    \item El sistema procesa los datos en el orden en que fueron recibidos.
                    \item El sistema produce un informe de análisis después de procesar un lote completo de datos.
                \end{enumerate}   
        
            \item \textbf{Respuestas a situaciones anormales}
                \begin{enumerate}
                    \item El sistema emite una alerta si se detectan valores fuera del rango esperado en cualquiera de los parámetros (pH, temperatura, CO).
                    \item El sistema registra en un log cualquier error encontrado durante el análisis de datos.
                \end{enumerate}   
       
            \item \textbf{Efecto de los parámetros}
                \begin{enumerate}
                    \item Se asegura que los datos incluyan un timestamp válido y estén ordenados cronológicamente para garantizar la correcta secuencia temporal del análisis.
                    \item El módulo 2 se adapta la frecuencia de los datos recibidos desde la base de datos paara optimizar
                    el análisis de datos.
                \end{enumerate}   
        
            \item \textbf{Relación entre las salidas y las entradas}
                \begin{enumerate}
                    \item El módulo 2 actualiza la base de datos con los resultados del análisis para su posterior consulta.
               \end{enumerate}
        \end{enumerate}
\item \textbf{RNF02}\label{it:RNF02}
            \item \begin{enumerate}
                    \item El mpdulo 2 debe ser capaz de manejar múltiples solicitudes de análisis de datos de diferentes usuarios sin degradar el rendimiento.
                    \item El módulo 2 debe ser escalable para soportar un aumento en el volumen de datos a analizar.
            \end{enumerate}
\end{enumerate}
  

\subsection{Módulo 3}
\begin{enumerate}
\item \label{it:RF05} \textbf{RF05-Base de datos}
    \begin{enumerate}
            \item \textbf{Validez de las entradas}
                \begin{enumerate}
                    \item La Base de datos valida que los datos recibidos del módulo 1 estén completos y no contengan valores nulos.
                    \item La Base de datos deberá comprobar que todos los paquetes de datos provenientes de los sensores incluyan la marca de tiempo asociada y su ID único del microcontrolador
                    para asociarlo con su usuario correspondiente.
                    \item La Base de datos valida las claves de acceso de los usuarios por medio de la página web.
                \end{enumerate}   
            
            \item \textbf{Secuencia exacta de operaciones}
                \begin{enumerate}
                    \item La Base de datos almacena los datos recibidos en el orden en que fueron recibidos.
                    \item La Base de datos permite consultas y recuperaciones de datos por parte del módulo de análisis de datos.
                    \item La Base de datos envia los datos almacenados a la interfaz web para su visualización cuando sea solicitado por parte del usuario.
                \end{enumerate}   
        
            \item \textbf{Respuestas a situaciones anormales}
                \begin{enumerate}
                    \item La Base de datos emite una alerta si se detectan intentos no autorizados de acceso.
                    \item La Base de datos registra en un log cualquier error encontrado durante las operaciones de almacenamiento o recuperación de datos.
                \end{enumerate}   
       
            \item \textbf{Efecto de los parámetros}
                \begin{enumerate}
                    \item La Base de datos garantiza la compatiblidad con el formato de datos del módulo 1 y 2.
                    \item La Base de datos adapta la frecuencia de datos recibidos por parte del módulo 1.
                    \item La Base de datos optimiza las consultas si se detectan patrones comunes en las solicitudes de datos.
                    \item La Base de datos garantiza una alta dispnibilidad y escalabilidad horizontal de cara a los usuarios.
                    \item La Base de datos solo debe permitir el acceso a los datos de los sensores a su usuario correspondientes y al admin, implementando mecanismos de autenticación y autorización adecuados.
                \end{enumerate}   
        
            \item \textbf{Relación entre las salidas y las entradas}
                \begin{enumerate}
                    \item La Base de datos permite la entrada de datos desde el módulo 1 para su almacenamiento.
                    \item La Base de datos permite la entrada de solicitudes desde el módulo 2 y envía los datos necesarios para el análisis.
                    \item La Base de datos permite la entrada de solicitudes desde el módulo 4 y envía los datos correspondientes para su visualización en la página web.
                \end{enumerate}
    \end{enumerate}
\item \label{it:RNF03} \textbf{RNF03}
            \item \begin{enumerate}
                    \item El mpdulo 3 debe ser capaz de manejar múltiples solicitudes de almacenamiento y recuperación de datos de diferentes usuarios sin degradar el rendimiento.
                    \item El módulo 3 debe ser escalable horizontalmente para soportar un aumento de usuarios y de datos almacenados.
                    \item La Base de datos proporciona acceso rápido y eficiente a los datos almacenados para su análisis y visualización.
                    \item La Base de datos garantiza una consistncia e integridad de los datos almacenados de cada usuario. 
            \end{enumerate}
 \end{enumerate}

\subsection{Módulo 4}
\begin{enumerate}
    \item \label{it:RF07} \textbf{RF07-Página Web}
        \begin{enumerate}
                \item \textbf{Validez de las entradas}
                    \begin{enumerate}
                        \item El entorno de front de la página web debe permitir compatibilidad con el formato de datos del módulo 1,2 y 3 para su futura visualización.
                        \item El entorno de front end de la página web 
                        debe integrar una interfaz renderizada para gráficos y formularios interactivos para la visualización de datos en tiempo real.
                
                    \end{enumerate}   
                
                \item \textbf{Secuencia exacta de operaciones}
                    \begin{enumerate}
                        \item La página web debe integrar un sistema de autenticación seguro para que los usuarios puedan iniciar sesión con sus credenciales.
                        \item La página web debe permitir a los usuarios visualizar los datos de sus fermentaciones en tiempo real.
                    \end{enumerate}   
            
                \item \textbf{Respuestas a situaciones anormales}
                    \begin{enumerate}
                        \item El entorno de front de la página web debe registrar en un log cualquier intento fallido de conexion hacia la base de datos.
                    \end{enumerate}   
        
                \item \textbf{Efecto de los parámetros}
                    \begin{enumerate}
                        \item El entorno de front de la págia web debe poder permitir tener múltiples usuarios conectados de manera simultanea sin degradar el rendimiento.
                        \item El entorno de front de la págia web debe escalar gráficos según el volumen de información obtenida de la base de datos.
                    \end{enumerate}   
            
                \item \textbf{Relación entre las salidas y las entradas}
                    \begin{enumerate}
                        \item El entorno de front de la página web debe permitir una conexión bidireccional con la base de datos para enviar y recibir datos en tiempo real.
                    \end{enumerate}
        \end{enumerate}

    \item \label{it:RF08}  \textbf{RF08-Página Web:Iniciar Sesión}
        \begin{enumerate}
                \item \textbf{Validez de las entradas}
                    \begin{enumerate}
                        \item La página web solicita por medio de un solo formulario de registro 
                        las credenciales(nombre y contraseña) de acceso del usuario o admin para su validacíon en la base de datos.
                        \item La página web debe permitir recuperar la contraseña en caso de olvido por medio de un correo electrónico asociado a la cuenta.
                    \end{enumerate}   
                
                \item \textbf{Secuencia exacta de operaciones}
                    \begin{enumerate}
                        \item El usuario ingresa sus credenciales en el formulario de inicio de sesión.
                        \item La página web envía las credenciales a la base de datos para su validación.
                        \item La base de datos verifica las credenciales y responde a la página web con el resultado.
                        \item Si las credenciales son válidas, la página web redirige al usuario a la página principal.
                    \end{enumerate}   
            
                \item \textbf{Respuestas a situaciones anormales}
                    \begin{enumerate}
                        \item Si las credenciales son inválidas, la página web muestra un mensaje de error y permite al usuario intentar iniciar sesión nuevamente.
                    \end{enumerate}   
        
                \item \textbf{Efecto de los parámetros}
                    \begin{enumerate}
                        \item La página web debe cifrar las credenciales del usuario o admin antes de enviarlas a la base de datos para garantizar la seguridad.
                    \end{enumerate}   
                \item \textbf{Relación entre las salidas y las entradas}
                    \begin{enumerate}
                        \item La página debe generar un token de sesión único para el usuario o admin al iniciar sesión exitosamente, que se utilizará para mantener la sesión activa.
                    \end{enumerate}
        \end{enumerate}
        
         \item \label{it:RF09} \textbf{RF09-Página Web:Iniciar/terminar una fermentación}
        \begin{enumerate}
                \item \textbf{Validez de las entradas}
                    \begin{enumerate}
                        \item La página web por medio de un formulario solicita los datos 
                        (cantidad de búlgaros, tipo de leche y cantidad) para iniciar una fermentación. 
                        \item La página web muestra la fermentación activa en el módulo 1 del usuario por medio de un grafico.
                        \item La página web permite al usuario registrar la finalización de la fermentación en el módulo 1.
                    \end{enumerate}   
                
                \item \textbf{Secuencia exacta de operaciones}
                    \begin{enumerate}
                        \item El ususario debe inicar la fermentación en el módulo 1 por medio del modo monitoreo
                        y posteriormente registrar los datos en la página web por medio del formulario.
                        \item La página web muestra el estado de la fermentación en tiempo real.
                        \item El usuario debe terminar la fermentación en el módulo 1
                        y posteriormente registrar la finalización en la página web. 
                        \item La página web actualiza el estado de la fermentación a "terminada" y muestra el analisis de los datos recopilados durante el proceso.
                    \end{enumerate}   
            
                \item \textbf{Respuestas a situaciones anormales}
                    \begin{enumerate}
                        \item La fermentación no puede ser iniciada si el módulo 1 no está encendido o este determina si la fermentación esta en malas condiciones desde el inicio.
                    \end{enumerate}   
        
                \item \textbf{Efecto de los parámetros}
                    \begin{enumerate}
                        \item La página web adapta la visualización del estado de la fermentación según los datos recibidos del módulo 1 en tiempo real.
                    \end{enumerate}   
            
                \item \textbf{Relación entre las salidas y las entradas}
                    \begin{enumerate}
                        \item La página web muestra los datos de la fermentación en tiempo real de pH, temperatura y CO2.
                    \end{enumerate}
        \end{enumerate}

            \item \label{it:RF10} \textbf{RF10-Página web:Historial}
        \begin{enumerate}
                \item \textbf{Validez de las entradas}
                    \begin{enumerate}
                        \item La página web por medio de un formulario solicita la o las fermentaciónes específicas del usuario para mostrar o comparar en su historial.
                        \item La página web debe mostrar el historial por medio de gráficos y tablas de las fermentaciones pasadas del usuario.
                    \end{enumerate}   
                
                \item \textbf{Secuencia exacta de operaciones}
                    \begin{enumerate}
                        \item La página web por medio de la base de datos valida que el usuario tenga permisos para acceder al historial solicitado.
                    \end{enumerate}   
            
                \item \textbf{Respuestas a situaciones anormales}
                    \begin{enumerate}
                        \item La página web muestra un mensaje de error y redirige a la página principal si no se encuentran fermentaciones pasadas asociadas al usuario
                    \end{enumerate}   
        
                \item \textbf{Efecto de los parámetros}
                    \begin{enumerate}
                        \item La página web adapta la visualización del historial según los datos recibidos de la base de datos.
                        \item La página web permite comparar múltiples fermentaciones segun el parametro especificado por el usuario.
                    \end{enumerate}   
            
                \item \textbf{Relación entre las salidas y las entradas}
                    \begin{enumerate}
                        \item Los gráficos y tablas deben mostrar los datos históricos de pH, temperatura y CO2 de las fermentaciones pasadas segun lo solicite el usuario.
                    \end{enumerate}
        \end{enumerate}

          \item \label{it:RF11} \textbf{RF11-Página web:administrador}
        \begin{enumerate}
                \item \textbf{Validez de las entradas}
                    \begin{enumerate}
                        \item El administrador por medio de un formulario que le solicite nombre,
                        edad, correo,contraseña, municipio y categoria(productor inicial o raíz). 
                        puede crear, suspender o activar usuarios del sistema.
                        \item El administrador puede visualizar todas las fermentaciones activas y pasadas de todos los usuarios.
                    \end{enumerate}   
                
                \item \textbf{Secuencia exacta de operaciones}
                    \begin{enumerate}
                        \item El administrador ingresa los datos del usuario en el formulario para crear un nuevo usuario.
                        \item La página web envía los datos a la base de datos para crear el nuevo usuario.
                        \item La base de datos confirma la creación del usuario y responde a la página web con el resultado.
                        \item Si el administrador desea suspender un usuario, selecciona el usuario
                        de una lista y confirma la suspensión.
                        \item La página web envía la solicitud de suspensión a la base de datos.
                    \end{enumerate}   
            
                \item \textbf{Respuestas a situaciones anormales}
                    \begin{enumerate}
                        \item El administrador recibe un mensaje de error si intenta crear un usuario con un nombre o correo ya existente.
                        \item El administrador recibe un mensaje de confirmación al suspender un usuario exitosamente.
                    \end{enumerate}   
        
                \item \textbf{Efecto de los parámetros}
                    \begin{enumerate}
                        \item En caso de crear un usuario con categoria "productor raíz", la página debe solicitar información sobre de que otor usuario esta asociados.
                    \end{enumerate}   
            
                \item \textbf{Relación entre las salidas y las entradas}
                    \begin{enumerate}
                        \item El formulario debe solicitar los datos necesarios para crear un nuevo usuario.
                        \item La página web debe mostrar una lista actualizada de todos los usuarios del sistema, incluyendo su estado (activo o suspendido).
                    \end{enumerate}
        \end{enumerate}
        \item \label{it:RNF04} \textbf{RNF04}
            \item \begin{enumerate}
                    \item El mpdulo 4 debe ser capaz soportar multiples usuarios conectados de manera simultanea sin degradar el rendimiento.
                    \item El módulo 4 debe ofrecer una interfaz amigable e intuitiva de cara al usuarios.
            \end{enumerate}
 \end{enumerate}

\subsection{Servidor}
\begin{enumerate}
\item \label{it:RF12} \textbf{RF12-Servidor}
    \begin{enumerate}
            \item \textbf{Validez de las entradas}
                \begin{enumerate}
                    \item El entorno de desarrollo del servidor debe permitir compatibilidad con el formato de datos del módulo 1,2,3 y 4 para su futura integración.
                    \item El entorno de desarrollo del servidor debe gestionar las solicitudes de los diferentes módulos de manera eficiente.
                    \item El entorno de desarrollo del servidor debe implementar mecanismos de seguridad para proteger los datos transmitidos entre los módulos.
                    \item El entorno de desarrollo del servidor debe manejar múltiples conexiones simultáneas sin degradar el rendimiento.
                \end{enumerate}   
            
            \item \textbf{Secuencia exacta de operaciones}
                \begin{enumerate}
                    \item El servidor recibe datos del módulo 1 y los almacena en la base de datos del módulo 3.
                    \item El servidor recibe solicitudes de análisis de datos del módulo 2 y envía los datos necesarios desde la base de datos.
                    \item El servidor recibe solicitudes de la página web del módulo 4 y envía los datos correspondientes desde la base de datos.
                \end{enumerate}   
        
            \item \textbf{Respuestas a situaciones anormales}
                \begin{enumerate}
                    \item El servidor emite una alerta si se detectan intentos no autorizados de acceso.
                    \item El servidor registra en un log cualquier error encontrado durante las operaciones de transmisión de datos entre los módulos.
                \end{enumerate}   
       
            \item \textbf{Efecto de los parámetros}
                \begin{enumerate}
                    \item El servidor debe adaptarse a la gestión de solicitudes según el volumen de datos transmitidos entre los módulos.
                \end{enumerate}   
        
            \item \textbf{Relación entre las salidas y las entradas}
                \begin{enumerate}
                    \item El servidor deber permitir la entrada de datos desde el módulo 1 y enviarlos al módulo 3 para su almacenamiento.
                    \item El servidor debe permitir la entrada de solicitudes desde el módulo 2 y enviar los datos necesarios desde el módulo 3.
                    \item El servidor debe permitir la entrada de solicitudes desde el módulo 4 y enviar los datos correspondientes desde el módulo 3.
                \end{enumerate}
    \end{enumerate}
      \item \label{it:RNF04} \textbf{RNF05}
            \item \begin{enumerate}
                    \item El servidor debe garantizar la integración y comunicación entre todos lo módulos del sistema.
                    \item El servidor debe ser escalable para soportar un aumento en el volumen de datos y solicitudes entre los módulos.
                    \item El servidor debe implementar medidas de seguridad para proteger los datos transmitidos entre los módulos
            \end{enumerate}
 \end{enumerate}
